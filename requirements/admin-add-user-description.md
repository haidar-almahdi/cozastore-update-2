# وصف متطلب: إضافة مستخدم (Admin - Add User)

## نظرة عامة
هذا المتطلب يسمح للمدير بإضافة مستخدم جديد.

---

## الفاعلون (Actors)
- **Admin (المدير)**: مدير النظام

---

## الشروط المسبقة (Preconditions)
1. المستخدم مسجل دخول كمدير

---

## الشروط اللاحقة (Postconditions)
1. يتم إنشاء مستخدم جديد في قاعدة البيانات
2. يتم تعيين الدور المحدد للمستخدم (customer/admin)
3. يتم تشفير كلمة المرور قبل الحفظ

---

## السيناريو الأساسي (Main Flow)

### 1. فتح نموذج الإضافة
- المدير يضغط "Add User"
- النظام يعرض نموذج إضافة مستخدم

### 2. إدخال البيانات
- المدير يدخل: الاسم، البريد، كلمة المرور، الدور

### 3. حفظ المستخدم
- المدير يضغط "Save"
- النظام يحفظ المستخدم الجديد

---

## السيناريوهات البديلة (Alternative Flows)

### A1: إلغاء الإضافة
- **الشرط**: المدير يقرر إلغاء العملية.
- **الإجراء**:
  - المدير يضغط على زر "Cancel".
  - النظام يعود لقائمة المستخدمين دون حفظ.

### A2: البريد الإلكتروني مكرر
- **الشرط**: المدير يدخل بريد إلكتروني مسجل مسبقاً.
- **الإجراء**:
  - النظام يتحقق من البريد.
  - النظام يعرض رسالة خطأ "البريد الإلكتروني مستخدم بالفعل".
  - يطلب النظام إدخال بريد آخر.

## السيناريوهات الاستثنائية (Exceptional Flows)

### E1: فشل في قاعدة البيانات
- **الشرط**: خطأ في الاتصال بقاعدة البيانات.
- **الإجراء**:
  - النظام يعرض رسالة خطأ عامة.
  - لا يتم حفظ المستخدم.

### E2: كلمة المرور ضعيفة
- **الشرط**: المدير يدخل كلمة مرور لا تحقق شروط الأمان.
- **الإجراء**:
  - النظام يعرض رسالة توضح شروط كلمة المرور.
  - يطلب النظام إدخال كلمة مرور أقوى.

---

## البيانات المطلوبة (Required Data)

### Input:
- **name**: الاسم (required|string|max:255)
- **email**: البريد الإلكتروني (required|string|email|max:255|unique:users)
- **password**: كلمة المرور (required|string|min:8|confirmed)
- **role**: الدور (required|in:user,admin)

> **ملاحظة**: في الكود الفعلي، الأدوار المسموحة هي `user` و `admin` (ليس `customer`)

---

## الجداول المتأثرة (Affected Tables)
1. **users**: إدراج مستخدم جديد

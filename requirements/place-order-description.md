# وصف متطلب: إنشاء طلب (Place Order)

## نظرة عامة
هذا المتطلب يسمح للمستخدم المسجل بإنشاء طلب شراء من المنتجات الموجودة في سلة التسوق الخاصة به.

---

## الفاعلون (Actors)
- **Customer (المستخدم)**: المستخدم المسجل الذي يريد إتمام عملية الشراء

---

## الشروط المسبقة (Preconditions)
1. المستخدم مسجل دخول في النظام
2. سلة التسوق تحتوي على منتج واحد على الأقل
3. جميع المنتجات في السلة متوفرة في المخزون
4. المنتجات نشطة (is_active = true)

---

## الشروط اللاحقة (Postconditions)
1. يتم إنشاء طلب جديد في قاعدة البيانات
2. يتم إنشاء عناصر الطلب (OrderItems) لكل منتج في السلة
3. يتم تحديث مخزون المنتجات (تقليل الكمية)
4. يتم منح نقاط ولاء للمستخدم (1% من إجمالي الطلب)
5. يتم إفراغ سلة التسوق
6. حالة الطلب تكون "pending" (معلق)

---

## السيناريو الأساسي (Main Flow)

### 1. عرض السلة
- المستخدم ينتقل إلى صفحة السلة
- النظام يعرض المنتجات الموجودة في السلة
- النظام يعرض الإجمالي الكلي

### 2. الانتقال للدفع
- المستخدم يضغط على زر "Checkout"
- النظام يتحقق من أن السلة ليست فارغة
- النظام يتحقق من توفر المنتجات في المخزون
- النظام يعرض صفحة الدفع مع نموذج بيانات الشحن

### 3. إدخال بيانات الطلب
- المستخدم يدخل:
  - اسم المستلم (Shipping Name)
  - رقم الهاتف (Shipping Phone)
  - عنوان الشحن (Shipping Address)
  - ملاحظات إضافية (Notes) - اختياري

### 4. إنشاء الطلب
- المستخدم يضغط على زر "Place Order"
- النظام يتحقق من صحة البيانات المدخلة
- النظام يتحقق مرة أخرى من توفر المنتجات
- النظام يبدأ معاملة قاعدة بيانات (Transaction)

### 5. حفظ الطلب
- النظام ينشئ طلب جديد مع:
  - رقم طلب فريد (Order Number)
  - معرف المستخدم (User ID)
  - الإجمالي الكلي (Total Amount)
  - حالة الطلب: "pending"
  - بيانات الشحن

### 6. إنشاء عناصر الطلب
- لكل منتج في السلة:
  - النظام ينشئ OrderItem جديد
  - النظام ينسخ بيانات المنتج (السعر، الكمية، المقاس، اللون)
  - النظام يربط العنصر بالطلب

### 7. تحديث المخزون
- لكل منتج في الطلب:
  - النظام يقلل كمية المخزون بمقدار الكمية المطلوبة

### 8. منح نقاط الولاء
- النظام يحسب النقاط (1% من إجمالي الطلب)
- النظام ينشئ معاملة نقاط ولاء جديدة
- النظام يضيف النقاط لرصيد المستخدم

### 9. إفراغ السلة
- النظام يحذف جميع المنتجات من السلة

### 10. تأكيد الطلب
- النظام يحفظ المعاملة (Commit Transaction)
- النظام يعيد توجيه المستخدم لصفحة تأكيد الطلب
- النظام يعرض:
  - رقم الطلب
  - تفاصيل الطلب
  - الإجمالي الكلي
  - تاريخ التسليم المتوقع

---

## السيناريوهات البديلة (Alternative Flows)

### A1: السلة فارغة
- **الشرط**: المستخدم يحاول الدفع والسلة فارغة
- **الإجراء**: 
  - النظام يعرض رسالة "السلة فارغة"
  - النظام يعيد توجيه المستخدم لصفحة المنتجات

### A2: منتج غير متوفر
- **الشرط**: أحد المنتجات في السلة غير متوفر أو نفذ من المخزون
- **الإجراء**:
  - النظام يعرض رسالة خطأ
  - النظام يعرض قائمة بالمنتجات غير المتوفرة
  - النظام يطلب من المستخدم تحديث السلة

### A3: بيانات غير صحيحة
- **الشرط**: المستخدم لم يدخل جميع البيانات المطلوبة أو البيانات غير صحيحة
- **الإجراء**:
  - النظام يعرض رسائل خطأ للحقول المطلوبة
  - النظام يبقي المستخدم في صفحة الدفع
  - المستخدم يصحح البيانات ويحاول مرة أخرى

### A4: خطأ في قاعدة البيانات
- **الشرط**: حدث خطأ أثناء حفظ الطلب
- **الإجراء**:
  - النظام يلغي المعاملة (Rollback Transaction)
  - النظام يعرض رسالة خطأ عامة
  - لا يتم تغيير أي بيانات (السلة، المخزون، النقاط)

---

## قواعد العمل (Business Rules)

1. **رقم الطلب الفريد**:
   - يتم توليد رقم طلب فريد لكل طلب
   - الصيغة: ORD-{timestamp}-{random}

2. **حساب الإجمالي**:
   - الإجمالي = مجموع (سعر المنتج × الكمية) لكل منتج في السلة

3. **نقاط الولاء**:
   - يحصل المستخدم على 1% من إجمالي الطلب كنقاط ولاء
   - النقاط = (Total Amount × 0.01)
   - يتم تقريب النقاط لأقرب عدد صحيح

4. **تحديث المخزون**:
   - يتم تقليل المخزون فوراً عند إنشاء الطلب
   - إذا تم إلغاء الطلب لاحقاً، يتم إرجاع المخزون

5. **حالة الطلب الافتراضية**:
   - جميع الطلبات الجديدة تبدأ بحالة "pending"

---

## البيانات المطلوبة (Required Data)

### Input (المدخلات):
- **shipping_name**: اسم المستلم (required|string|max:255)
- **shipping_phone**: رقم الهاتف (required|string|max:20)
- **shipping_address**: العنوان الكامل (required|string|max:500)
- **notes**: ملاحظات إضافية (nullable|string|max:1000)
- **redeem_blocks**: عدد بلوكات النقاط المراد استبدالها (optional|integer) - نظام الولاء

### Output (المخرجات):
- يتم إنشاء طلب جديد في `orders` مع order_number عشوائي
- يتم نسخ عناصر السلة إلى `order_items`
- يتم خصم المخزون من `products`
- ي تم حذف السلة (cart cleared)
- **نظام الولاء**: يتم منح 3 نقاط عند إنشاء الطلب + خصم إذا تم استبدال النقاط

> **ملاحظة**: يتم حساب Shipping = 2% من الإجمالي، والتحقق من المخزون قبل إنشاء الطلب الكلي
- **status**: حالة الطلب (pending)
- **created_at**: تاريخ إنشاء الطلب
- **order_items**: قائمة عناصر الطلب
- **loyalty_points_earned**: النقاط المكتسبة

---

## الجداول المتأثرة (Affected Tables)

1. **orders**: إدراج طلب جديد
2. **order_items**: إدراج عناصر الطلب
3. **products**: تحديث المخزون (stock)
4. **cart_items**: حذف عناصر السلة
5. **carts**: تحديث حالة السلة
6. **loyalty_point_transactions**: إدراج معاملة نقاط جديدة
7. **users**: تحديث رصيد النقاط (loyalty_points_balance)

## الأمان (Security)

1. المستخدم يجب أن يكون مسجل دخول (Authenticated)
2. المستخدم يمكنه فقط إنشاء طلبات لنفسه
3. يتم التحقق من صحة البيانات على مستوى الخادم (Server-side validation)
4. استخدام CSRF Token لحماية النموذج
5. استخدام Database Transaction لضمان سلامة البيانات

---

## الأداء (Performance)

1. استخدام Database Transaction لتحسين الأداء
2. تحميل بيانات السلة مع العلاقات (Eager Loading)
3. استخدام Indexes على الحقول المستخدمة في البحث
4. Cache لبيانات المنتجات المتكررة
